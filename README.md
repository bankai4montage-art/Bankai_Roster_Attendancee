# Bankai — Roster & Attendance

نظام داخلي لإدارة **الروستر والحضور والغرامات** لفرعين (`QCD 1` و `QCD 2`).
واجهة عربية RTL بالكامل، بدون أي build step.

## التشغيل

```bash
pip install -r requirements.txt
export ADMIN_PASSWORD="<كلمة مرور قوية>"
uvicorn app:app --host 0.0.0.0 --port 8000
```

ثم افتح <http://localhost:8000> — قاعدة البيانات `bankai.db` بتتولّد تلقائيًا.

## متغيرات البيئة

| المتغير | الافتراضي | الوظيفة |
| --- | --- | --- |
| `ADMIN_PASSWORD` | `ChangeThisPassword123!` | حساب الأدمن (كل الصلاحيات). **لازم تتغيّر في الإنتاج.** |
| `SUPERVISOR_PASSWORD` | `""` | حساب المشرف العام (مشاهدة + تعديل الحضور اليومي). فاضية = مقفول. |
| `SUPERVISOR_BRANCH_PASSWORDS` | `""` | مشرف لكل فرع بصيغة `QCD 1=باسورد;QCD 2=باسورد`. المسجّل بكلمة مرور الفرع يقدر يوافق/يرفض طلبات الحضور جايه من DAS **لفرعه فقط**. لما متحدة، المشرف العام يبقى مشاهدة للطلبات دي من غير قرار. |
| `SUPERVISOR_ACCOUNTS` | `""` | حسابات مشرفين بالاسم بصيغة `الاسم:الباسورد:الفرع` مفصولة بـ `;` أو `,`. كل مشرف يشوف البيانات والحضور وطلبات DAS والتقارير والغرامات **لفرعه فقط** (فلترة على السيرفر)، من غير جدول ولا إعدادات، وكل حاجة يعملها — حضور، موافقة، غرامة — بتتسجل باسمه (عمود «بواسطة»/«سجّلها»). |
| `DAS_SECRET` | `""` | مفتاح سر واجهات الربط مع DAS (`/api/das/*`). لازم نفس قيمة `ROSTER_DAS_SECRET` على سيرفر DAS. فاضية = واجهات الربط مقفولة تمامًا. |
| `SECRET_KEY` | مشتق من `ADMIN_PASSWORD` | توقيع جلسات الدخول. تغييره يبطّل كل الجلسات القائمة. |
| `DATABASE_URL` | `sqlite:///./bankai.db` | الصورة على Railway بتحدده لـ `sqlite:////data/bankai.db`. |
| `PORT` | `8000` | Railway بيحدده تلقائيًا. |

> ⚠️ تغيير `ADMIN_PASSWORD` مع عدم تحديد `SECRET_KEY` بيغيّر المفتاح المشتق، فكل المستخدمين لازم يسجّلوا الدخول من جديد.

## ملاحظات تشغيلية

- **نسخة ملفات الواجهة تلقائية.** `index.html` فيه `?v=__ASSET_V__` والسيرفر بيستبدلها ببصمة محتوى
  لـ `style.css` + `app.js` + `ui.js` عند كل طلب — يعني مفيش حاجة تنسى تزوّد رقم النسخة بعد النشر.
- **تغييرات قاعدة البيانات** بتم من `ensure_columns()` (إضافة أعمدة idempotent)، مفيش Alembic.
- **إجراءات لا رجعة فيها:** `POST /api/admin/wipe-attendance` بيمسح كل سجل الحضور. خُد نسخة
  احتياطية من الإعدادات قبلها.
- **قفل تسجيل الدخول:** 8 محاولات فاشلة من نفس الـ IP ⇒ قفل 5 دقايق (في الذاكرة، بيروح مع restart).

## طلبات الحضور من DAS (Check In / Check Out)

صفحة المندوب في DAS فيها زرار **تسجيل حضور** و**تسجيل انصراف**؛ الطلب بيجي هنا
Pending في لوحة الأدمن/المشرف، قسم **«طلبات الحضور من DAS»** على داشبورد اليوم.
الموافقة بتسجّل حضور رسمي في جدول `attendance` (Present بدون غرامة، والملاحظة بتوثّق
وقت الطلب الفعلي بتوقيت القاهرة)، والرفض بيرجّع القرار للمندوب في DAS.

**القواعد المطبّقة على مستوى السيرفر:**

- الموظف بيتعرّف من `employee_code` حصرًا (الكود اللي DAS كتبه على الموظف من شاشة
  ربط الروستر) — الاسم عمرو ما بيتسخدم للربط.
- وقت الطلب = وقت استلام سيرفر الروستر (مش وقت جهاز المندوب ولا وقت الموافقة).
- الشيفت الليلي: الانصراف بيرث يوم الحضور، فما بينلفّش بعد منتصف الليل على يوم تاني.
- مفيش طلبين مفتوحين بنفس النوع لنفس المندوب في نفس يوم الشيفت (قيد يقيني)،
  ومفيش انصراف غير بعد حضور معتمد ملوش انصراف.
- كل نداء من DAS لازم يوصل مع هيدر `X-DAS-Secret` بقيمة `DAS_SECRET`
  (سر سيرفري مش بيروح للمتصفح).
- جدول `das_requests` بيتعمل من `create_all` مزامنة أول تشغيل، والموافقات بتنزل
  في تقارير الحضور والغرامات زي أي تسجيل حضور عادي بدون أي حسابات إضافية.

## واجهات الربط (مرجع قصير)

| الطلب | الوصف |
| --- | --- |
| `POST /api/das/requests` (X-DAS-Secret) | تسجيل طلب حضور/انصراف جديد من DAS → Pending. |
| `GET /api/das/requests?updated_since=...` (X-DAS-Secret) | مزامنة القرارات لجانب DAS. |
| `GET /api/das/requests/inbox` (توكن جلسة) | قائمة الطلبات في داشبورد المستخدم (المشرف المرتبط بفرع يشوف فرعه بس). |
| `POST /api/das/requests/{id}/decide` (توكن جلسة) | `{decision: "approve"\|"reject", note}` — الموافقة بتسجّل الحضور رسميًا. |
